# Control4 push — официальная интеграция Control4 на push

Официальная интеграция `control4` из Home Assistant, переведённая с опроса на push. Состояния
приходят от директора по WebSocket сразу, а не раз в 5 с. Ставится **поверх** официальной
(тот же домен `control4`): запись интеграции, устройства и сущности сохраняются.

Основа — PR [home-assistant/core#176238](https://github.com/home-assistant/core/pull/176238)
на коммите `4ddb176` (первый коммит этого репозитория — он без изменений). Наши правки —
второй коммит и далее:

- **`director_websocket.py`** — исправленный клиент WebSocket директора. В pyControl4 2.0.2
  (и в самом PR) после любого обрыва — перезагрузка директора, сбой сети — сокет больше
  не переподключается: переподключение открывает сессию, которая отвергает самоподписанный
  сертификат директора. PR при этом тихо скатывается в опрос раз в 60 с до суточной смены
  токена. Без переданной сессии та же библиотека вместо этого блокирует цикл событий
  загрузкой сертификатов на каждой попытке (pyControl4 #62). Здесь переподключение идёт через
  сессию HA, и выгрузка/смена токена во время простоя директора гасит старый цикл
  переподключения (иначе после возвращения директора — два сокета и дубли событий).
- `voluptuous` вместо `probatio` — чтобы ставилось на HA 2026.8 (probatio — с 2026.9).
- `manifest.json`: `version` (обязателен для пользовательской интеграции), владелец и ссылка.

## Что осталось от опроса

- **Резервная сверка раз в 60 с** по всем сущностям. Не основной путь данных, а страховка:
  push директора на части контроллеров теряет переменные (подтверждено на X4,
  lawtancool/hass-control4#50) — без сверки пропущенное событие висело бы до следующего.
  Если на объекте окажется, что push ничего не теряет, её можно убрать.
- **Медиаплееры — раз в 5 с**, как в PR: часть их состояния директор не шлёт.
- Настройка «интервал опроса» пропадает (старое значение игнорируется).

## Токен директора и облако Control4

Облако Control4 нужно только чтобы **выдать** токен директора (живёт 24 ч); дальше директор
проверяет его сам. Токен и срок хранятся в записи интеграции, поэтому:

- **перезапуск HA облака не требует**, пока токен не истёк (директор принимает его до конца,
  новый добывает цепочка обновления); версия директора берётся у брокера контроллера
  (`/api/v1/version`, локально, без авторизации);
- **обновление** начинается за 12 ч до истечения: при неудаче — повтор через 1, 2, 4 … мин,
  дальше каждые 30 мин, пока не получится (доступ к ресурсам Control4 из РФ бывает
  нестабильным часами);
- каждая неудачная попытка — **WARNING** в журнале (номер попытки, причина, когда следующая,
  сколько ещё действует текущий токен); если токен успел истечь — **ERROR**; успех после
  неудач — INFO;
- облако спрашивается и при запуске, если сохранённого токена нет или директор его отверг;
  облачный запрос ограничен 30 с (раньше висел до ~4 мин), неудача — **WARNING** (сам HA
  пишет повтор настройки только на INFO);
- к облаку каждый запрос идёт **по новому соединению**: сервер Control4 часто закрывает
  соединение, когда по нему приходит следующий запрос (`Server disconnected`).
- **Маршрут**: если контроллер ходит в облако через туннель, запросы HA к
  `apis.control4.com` должны идти туда же — от блокировок код интеграции не спасает.

## Установка

Нужен Home Assistant **2026.8+**.

1. HACS → меню ⋮ → **Custom repositories** → `https://github.com/deliriumxp/control4-push`,
   категория **Integration**.
2. Найти **Control4 push**, установить, перезапустить HA. В журнале будет предупреждение, что
   пользовательская интеграция `control4` заменяет встроенную, — так и задумано.

Без HACS — скопировать папку `custom_components/control4` в `/config/custom_components/control4`
(Samba, SSH или Studio Code Server) и перезапустить HA.

Откат: удалить в HACS (или стереть `/config/custom_components/control4`) и перезапустить HA —
вернётся встроенная, с той же записью и сущностями.

Подробный журнал на время проверки (`configuration.yaml`):

```yaml
logger:
  logs:
    custom_components.control4: debug
    pyControl4: debug
```

## Диагностика

Страница интеграции → ⋮ → **Скачать диагностику**: элементы света и штор с их сырыми
переменными так, как их отдаёт директор (пароль, логин и токен вырезаны). Нужна, когда
поведение зависит от того, что именно директор сообщает, — например, реле определилось
как диммер.

## Что проверить на железе

1. **Скорость.** Включить свет / двинуть штору с панели или из приложения Control4 — в HA
   состояние меняется за ~1 с, а не с задержкой до 5 с.
2. **Нет блокировок.** В журнале нет `Detected blocking call to load_default_certs` /
   `set_default_verify_paths`.
3. **Переподключение — главное.** Перезагрузить директор (или отключить ему сеть на 1–2 мин).
   В журнале: `WebSocket connection to Control4 lost, attempting reconnection`, после
   возвращения директора — `WebSocket connection to Control4 re-established`. Сущности снова
   доступны, и изменения опять приходят сразу, а не раз в минуту.
4. **Перезагрузка интеграции при лежащем директоре.** Пока директор недоступен — «Перезагрузить»
   интеграцию; после его возвращения одно действие даёт одно событие в журнале (не два).
5. **Сутки работы.** Через ~24 ч (смена токена директора) push продолжает работать.

## Тесты

```sh
uv venv -p 3.14 && uv pip install "homeassistant==2026.8.*" pytest-homeassistant-custom-component pyControl4==2.0.2
.venv/bin/python -m pytest
```

Тесты PR (директор замокан) плюс `tests/test_director_websocket.py`: фейковый директор
(TLS с самоподписанным сертификатом, Engine.IO v3 / Socket.IO v2) — переподключение после
обрыва без блокирующих вызовов, остановка цикла переподключения при выгрузке и контрольный
тест, что штатный клиент pyControl4 2.0.2 после обрыва не переподключается.
